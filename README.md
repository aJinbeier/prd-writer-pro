# PRD协作专家 (prd-writer-pro)

资深产品经理协作技能，与产品负责人共同撰写**可直接交付开发**的 PRD 文档。

## 核心能力

- **实体先行建模**：先定义核心实体、属性、关系和业务规则，再展开功能
- **四层规格写法**：页面结构 → 字段定义（8维度）→ 交互规则 → 业务规则，写到开发无歧义
- **状态机完整**：每个有生命周期的实体必须画清状态、流转条件、终态
- **全局规范统一**：Toast、分页、编号、安全等统一定义不重复
- **合规内建**：隐私加密、脱敏、审计贯穿各模块
- **版本管理**：先备份再改，每次修改列变更清单，追加更新记录

## 适用场景

- 撰写新产品的 PRD / 产品需求文档
- 细化已有需求到可开发粒度
- 功能规格说明书、产品设计文档
- 需求评审前的文档结构化整理

## 使用方式

将 `SKILL.md` 的内容作为 AI 助手的系统指令或技能加载，在撰写 PRD 时即可获得：

1. 标准的 11 章 PRD 文档结构
2. 页面-字段-交互-规则四层展开方法
3. 质量自检清单
4. 修改清单和版本管理规范

## 文档结构标准

```
1. 文档信息（版本记录 + 更新记录）
2. 项目背景与目标
3. 核心概念与名词
4. 业务流程
5. 产品架构
6. 功能规格 — 后台
7. 功能规格 — C端
8. 数据模型
9. 非功能性规格
10. 运营操作指南
11. 需求列表
```

## 质量自检

- [ ] 每个核心实体有完整属性定义和业务规则
- [ ] 全文术语一致，无同义词混用
- [ ] 每个页面字段/交互/规则写透，开发不需追问
- [ ] 状态机完整，无悬空状态
- [ ] C端与后台数据对应
- [ ] 异常流程和边界条件有覆盖
- [ ] 一期做/不做/后续优化三部分清晰
- [ ] 全局规范定义一次不重复
- [ ] 合规要求贯穿各模块
- [ ] 更新记录已追加，修改清单已列出
- [ ] 备份已创建
